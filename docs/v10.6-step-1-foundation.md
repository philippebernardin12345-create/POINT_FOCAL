## Schéma V10.6 ajouté

- `schema_migrations`
- `v106_runtime_state`
- `v106_global_sponsorships`
- `v106_phase_transition_events`

## Relations

- `v106_runtime_state.root_user_id -> users.id`
- `v106_global_sponsorships.sponsor_user_id -> users.id`
- `v106_global_sponsorships.child_user_id -> users.id`

## Contraintes et index

- singleton garanti dans `v106_runtime_state` via clé primaire booléenne fixée à `true`
- `phase IN ('LEADER_LAUNCH', 'NORMAL_OPERATION')`
- `slot_no IN (1, 2)`
- `UNIQUE (sponsor_user_id, slot_no)`
- `UNIQUE (child_user_id)` retenue pour un sponsoring global unique par enfant
- `UNIQUE (to_phase)` sur `v106_phase_transition_events` pour empêcher le doublon de transition finale

## Fonctions SQL

- `v106_assign_global_sponsor(...)`
  - verrouille sponsor et enfant avec `FOR UPDATE`
  - choisit `slot 1` puis `slot 2`
  - s'appuie sur les contraintes SQL pour la seconde barrière anti-concurrence
- `v106_transition_phase_to_normal_operation()`
  - verrouille la ligne singleton
  - recalcule le nombre de leaders à partir des colonnes réellement disponibles dans `users`
  - ne bascule qu'une fois
  - journalise la transition dans `v106_phase_transition_events`

## Root

- abstraction Node.js :
  - `setRootUser(...)`
